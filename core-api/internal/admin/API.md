# Admin Module API (`internal/admin`)

> **Owner:** Member 7 | **Base path:** `/api/v1` | **Server:** Core API `:8080`
> **Code:** `transport/http.go` | **Module docs:** [README.md](README.md)

## Conventions

- **Auth:** admin routes need `Authorization: Bearer <access JWT>` with role `ADMIN`. The one exception is the delivery report, which also admits `DISPATCHER`. No token or an invalid token is `401`; any other role is `403`. These two responses come from Member 1's identity middleware (codes `AUTH_UNAUTHORIZED`, `AUTH_MALFORMED_HEADER`, `AUTH_INVALID_TOKEN`, `AUTH_TOKEN_EXPIRED`, `AUTH_FORBIDDEN`).
- **Request bodies:** `Content-Type: application/json`, at most 1 MB, exactly one JSON object. Unknown fields are refused with `400 BAD_REQUEST`.
- **Success envelope:** `{"data": ...}`. Admin responses send `Cache-Control: no-store`.
- **Paged lists** (`GET /api/v1/admin/zones`, `GET /api/v1/admin/audit-logs`; `docs/contracts/api-conventions.md` §2.2). Query: `?page=` (whole number from 1, default 1) and `?per_page=` (1 to 100, default 20). A value outside that range, or not a whole number, is `422 VALIDATION_FAILED`. The old `?limit=` is gone and is ignored. The answer carries a `meta` object next to `data`:

  ```json
  {
    "data": [ { "...": "..." } ],
    "meta": { "page": 2, "per_page": 10, "total_items": 45, "total_pages": 5 }
  }
  ```

  A page past the end returns `"data": []` with the real `total_items`. `total_pages` is `0` when there are no items.
- **Error envelope** (`docs/contracts/api-conventions.md` §2.3):

  ```json
  {
    "error": {
      "code": "VALIDATION_FAILED",
      "message": "Some fields are not valid",
      "correlation_id": "0193b2f4-7a1c-7d2e-9f10-3c4d5e6f7a8b",
      "timestamp": "2026-11-09T10:15:00Z"
    }
  }
  ```

  `correlation_id` is the request's `X-Request-ID` (sent by the client, or generated by the server). Messages are fixed and safe; they never contain SQL or internal details.
- **Optional header:** `X-Request-ID` (`^[a-zA-Z0-9_-]{1,128}$`). It is stored in `audit_logs.request_id`.

### Error codes

| Status | Code | When |
| :-- | :-- | :-- |
| 400 | `BAD_REQUEST` | Body is not one JSON object, has unknown fields, or wrong JSON types |
| 404 | `NOT_FOUND` | Zone id or setting key does not exist |
| 404 | `ZONE_NOT_FOUND` | No enabled zone covers the postal code (public lookup) |
| 409 | `CONCURRENT_MODIFICATION` | `version` is not the current version |
| 409 | `ZONE_POSTAL_CODE_CONFLICT` | A prefix overlaps a prefix of another zone |
| 409 | `ZONE_CODE_ALREADY_EXISTS` | The zone `id` or `code` is already used |
| 422 | `VALIDATION_FAILED` | A field breaks a rule (formats, lengths, ranges, enable an enabled zone) |
| 422 | `SETTING_UNKNOWN` | The setting key is not on the allowlist |
| 422 | `REASON_REQUIRED` | `reason` missing or not 10 to 500 characters |
| 500 | `INTERNAL_SERVER_ERROR` | Unexpected error (details in the server log only) |
| 503 | `TRY_AGAIN` | Lock timeout (2 s), deadlock or serialization failure. Safe to retry |
| 503 | `SERVICE_UNAVAILABLE` | Database unreachable or statement timeout |

### Zone object

| Field | Type | Rules |
| :-- | :-- | :-- |
| `id` | string | `^ZONE_[A-Z0-9_]{2,27}$`. Set on create, never changes |
| `code` | string | `^[A-Z0-9_-]{2,32}$`, unique |
| `name` | string | 1 to 120 characters after trimming |
| `description` | string | at most 500 characters; `""` when not set |
| `postal_prefixes` | string[] | 1 to 200 items, each `^[0-9]{3,5}$`, no duplicates, no overlap with other zones |
| `enabled` | boolean | `true` on create |
| `version` | integer | starts at 1, +1 per successful change |

## 1. Public zones

### `GET /api/v1/zones`

No auth. Lists **enabled** zones, ordered by name, for booking forms. With `postal_code`, returns the one enabled zone whose longest prefix starts that code.

| Query | Type | Rules |
| :-- | :-- | :-- |
| `postal_code` | string | optional, exactly 5 digits |

Successful responses send `Cache-Control: public, max-age=300`. Error responses are not cached.

**200, list:**

```json
{
  "data": [
    { "id": "ZONE_COLOMBO_01", "code": "CMB-01", "name": "Colombo Central" },
    { "id": "ZONE_KANDY_01", "code": "KDY-01", "name": "Kandy" }
  ]
}
```

**200, `?postal_code=00150`:**

```json
{ "data": { "id": "ZONE_COLOMBO_01", "code": "CMB-01", "name": "Colombo Central" } }
```

**Errors:** `422 VALIDATION_FAILED` (postal code not 5 digits, or sent twice), `404 ZONE_NOT_FOUND`.

## 2. Delivery zones (ADMIN)

### `GET /api/v1/admin/zones`

All zones, enabled and disabled, ordered by `id`, one page at a time.

| Query | Type | Rules |
| :-- | :-- | :-- |
| `page` | integer | optional, from 1, default 1 |
| `per_page` | integer | optional, 1 to 100, default 20 |

**200:**

```json
{
  "data": [
    {
      "id": "ZONE_COLOMBO_01",
      "code": "CMB-01",
      "name": "Colombo Central",
      "description": "Fort, Pettah and Galle Face",
      "postal_prefixes": ["00100", "00200", "00300"],
      "enabled": true,
      "version": 3
    }
  ],
  "meta": { "page": 1, "per_page": 20, "total_items": 1, "total_pages": 1 }
}
```

**Errors:** `422 VALIDATION_FAILED` (bad `page` or `per_page`).

### `GET /api/v1/admin/zones/{id}`

**200:** one zone object in `data`. **Errors:** `404 NOT_FOUND`.

### `POST /api/v1/admin/zones`

Creates an enabled zone (version 1) and writes a `ZONE_CREATED` audit row in the same transaction.

**Request:**

```json
{
  "id": "ZONE_COLOMBO_01",
  "code": "CMB-01",
  "name": "Colombo Central",
  "description": "Fort, Pettah and Galle Face",
  "postal_prefixes": ["00100", "00200", "00300"]
}
```

`id`, `code`, `name`, `postal_prefixes` are required; `description` is optional.

**201:** header `Location: /api/v1/admin/zones/ZONE_COLOMBO_01`, body:

```json
{
  "data": {
    "id": "ZONE_COLOMBO_01",
    "code": "CMB-01",
    "name": "Colombo Central",
    "description": "Fort, Pettah and Galle Face",
    "postal_prefixes": ["00100", "00200", "00300"],
    "enabled": true,
    "version": 1
  }
}
```

**Errors:** `400 BAD_REQUEST`, `422 VALIDATION_FAILED`, `409 ZONE_POSTAL_CODE_CONFLICT`, `409 ZONE_CODE_ALREADY_EXISTS`, `503 TRY_AGAIN`.

### `PATCH /api/v1/admin/zones/{id}`

Changes any of `code`, `name`, `description`, `postal_prefixes`. Omitted fields stay. `postal_prefixes`, when sent, replaces the whole list. Writes one `ZONE_UPDATED` audit row with the before and after zone.

**Request:**

```json
{
  "version": 1,
  "name": "Colombo Central Extended",
  "postal_prefixes": ["00100", "00200", "00300", "00400"],
  "reason": "Added Bambalapitiya to the central route"
}
```

| Field | Type | Rules |
| :-- | :-- | :-- |
| `version` | integer | required, the current version |
| `code`, `name`, `description` | string | optional, zone object rules |
| `postal_prefixes` | string[] | optional, zone object rules |
| `reason` | string | optional, stored in the audit row |

**200:** the updated zone. The version is +1 when anything changed. If nothing changed, the zone is returned with the same version and no audit row is written.

**Errors:** `404 NOT_FOUND`, `409 CONCURRENT_MODIFICATION`, `409 ZONE_POSTAL_CODE_CONFLICT`, `409 ZONE_CODE_ALREADY_EXISTS`, `422 VALIDATION_FAILED` (also when `version` is missing), `400 BAD_REQUEST`, `503 TRY_AGAIN`.

### `PATCH /api/v1/admin/zones/{id}/status`

Enables or disables a zone. Writes `ZONE_ENABLED` or `ZONE_DISABLED` to the audit log. A disabled zone disappears from the public list and lookup.

**Request:**

```json
{ "version": 2, "enabled": false, "reason": "Depot closed by flooding until further notice" }
```

All three fields are required. `reason` is 10 to 500 characters.

**200:** the updated zone (`"enabled": false`, `"version": 3`).

**Errors:** `422 REASON_REQUIRED`, `422 VALIDATION_FAILED` (zone already in that state), `404 NOT_FOUND`, `409 CONCURRENT_MODIFICATION`.

## 3. System settings (ADMIN)

### `GET /api/v1/admin/settings`

All settings, ordered by key.

**200:**

```json
{
  "data": [
    { "key": "ops.board_refresh_seconds", "value": 30, "value_type": "INTEGER", "description": "Dispatch board polling interval", "version": 1 },
    { "key": "ops.maintenance_banner", "value": "", "value_type": "STRING", "description": "Optional message shown on ops screens", "version": 1 },
    { "key": "reports.max_range_days", "value": 92, "value_type": "INTEGER", "description": "Longest report period in days", "version": 1 }
  ]
}
```

### `PUT /api/v1/admin/settings/{key}`

Replaces the value of one allowlisted setting and writes a `SETTING_CHANGED` audit row (before and after value, reason, actor).

**Request:**

```json
{ "version": 1, "value": 60, "reason": "Board polls too often at peak hours" }
```

| Field | Type | Rules |
| :-- | :-- | :-- |
| `version` | integer | required, the current version |
| `value` | JSON | required, at most 4096 bytes, type and range per key (see README §2.6) |
| `reason` | string | required, 10 to 500 characters |

**200:**

```json
{
  "data": { "key": "ops.board_refresh_seconds", "value": 60, "value_type": "INTEGER", "description": "Dispatch board polling interval", "version": 2 }
}
```

**Errors:** `422 SETTING_UNKNOWN`, `422 VALIDATION_FAILED`, `422 REASON_REQUIRED`, `404 NOT_FOUND`, `409 CONCURRENT_MODIFICATION`.

## 4. Audit log (ADMIN)

### `GET /api/v1/admin/audit-logs`

Audit rows, newest first, one page at a time. Rows from every module that writes `audit_logs` are included.

| Query | Type | Rules |
| :-- | :-- | :-- |
| `page` | integer | optional, from 1, default 1 |
| `per_page` | integer | optional, 1 to 100, default 20 |

**200:**

```json
{
  "data": [
    {
      "id": "6f1d2c3b-4a5e-4f60-8a7b-9c0d1e2f3a4b",
      "actor_id": "8b3e6a4c-1f2d-4e5a-9b6c-7d8e9f0a1b2c",
      "actor_role": "ADMIN",
      "action": "ZONE_UPDATED",
      "target_type": "ZONE",
      "target_id": "ZONE_COLOMBO_01",
      "previous_state": { "name": "Colombo Central", "version": 1 },
      "new_state": { "name": "Colombo Central Extended", "version": 2 },
      "reason": "Added Bambalapitiya to the central route",
      "request_id": "0193b2f4-7a1c-7d2e-9f10-3c4d5e6f7a8b",
      "created_at": "2026-11-09T10:15:00Z"
    }
  ],
  "meta": { "page": 1, "per_page": 20, "total_items": 1, "total_pages": 1 }
}
```

`previous_state` and `new_state` hold the full zone or `{"value": ...}` for settings; the example is shortened. `actor_id`, `previous_state`, `new_state`, `reason` and `request_id` may be `null`. The client IP and user agent are stored but not returned.

**Errors:** `422 VALIDATION_FAILED` (bad `page` or `per_page`).

## 5. Delivery report (ADMIN and DISPATCHER)

### `GET /api/v1/admin/reports/deliveries`

Deliveries per day over a period (SRS FR-ADM-008). **Role: `ADMIN` or `DISPATCHER`**; any other role is `403`. Read only, so it writes no audit row.

| Query | Type | Rules |
| :-- | :-- | :-- |
| `from` | date | required, `YYYY-MM-DD`, a Sri Lanka day |
| `to` | date | required, `YYYY-MM-DD`, not before `from` |

The period may not be longer than the `reports.max_range_days` setting (default 92 days, also used if the setting cannot be read). A longer period is `422 VALIDATION_FAILED`.

The numbers are read through a Go interface (`application.ReportReader`) that Members 2 and 3 will implement; this module never runs SQL on their tables. Until they do, a stand-in answers with empty days and says so in `source`.

**200:**

```json
{
  "data": {
    "from": "2026-10-01",
    "to": "2026-10-03",
    "days": [],
    "delivered": 0,
    "failed": 0,
    "success_rate": null,
    "source": "stand-in: no parcel data until Members 2 and 3 connect"
  }
}
```

| Field | Meaning |
| :-- | :-- |
| `days` | one row per day: `date`, `delivered`, `failed`, `returned` |
| `delivered`, `failed` | totals for the period |
| `success_rate` | `delivered / (delivered + failed)`, or `null` when there were no attempts |
| `source` | where the numbers came from; shows the stand-in text until real data is connected |

**Errors:** `401`, `403`, `422 VALIDATION_FAILED` (missing or bad date, `to` before `from`, period too long).

## 6. Merchant approval (hosted by Member 4, ADMIN only)

These three endpoints are **not** in this module. Member 4's merchants module (`internal/merchants/transport/http.go`) serves them, enforces `ADMIN` and writes their audit rows. Mounting the same paths here would make Core API fail at startup (duplicate route), so they are listed for completeness only. Request and response formats are in `internal/merchants/API.md`.

| Method and path | What it does |
| :-- | :-- |
| `GET /api/v1/admin/merchants` | Merchant list, `?status=&page=&per_page=` |
| `GET /api/v1/admin/merchants/{merchant_id}` | One merchant |
| `POST /api/v1/admin/merchants/{merchant_id}/{action}` | `approve`, `reject`, `suspend`, `reinstate` or `disable`; body needs `expected_version` and, for some actions, a `reason` |

`cmd/api/wiring_admin_test.go` checks that all three exist next to the admin routes and answer `401` without a token and `403` for any role except `ADMIN`.

Error codes on these routes are Member 4's (for example `MERCHANT_VERSION_CONFLICT`, `MERCHANT_INVALID_TRANSITION`) and are not changed by this module.
